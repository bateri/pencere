`move`, `press` and `release` over an editor have `place`, `{ editor =, at =, inside =, version = }`
(`inside`: the place was in a selection or at a caret before a press moved the caret): the place of its
document under the pointer (a word to say what it is of while the pointer rests on it, a name to go to
at a ⌘-click). A press in an editor is the editor's as well: it puts the caret.

The pointer's **rest** is told to a page that asks (`events = { "hover" }`): when it stays `hover.delay`
(0.3 s) over a word (the run a double click takes; not over spaces, the gutter, a gap, or past the end of
a line) the page is told `hover` with `kind = "dwell"` and the word's range and box, and the `hits`: the
styles with an `id` that hold the place under it (a diagnostic, a link), so that the page does not search
its own lists. It is told once however the pointer moves within the word; when the pointer goes from a
word it was told of the page is told `kind = "leave"` at once (what a card does then, how long it waits
and whether the pointer came onto it is the page's: `@pencere/ui`'s `popover` does it, [The kit's library](library.md#pencereui)). A scroll,
a key, a press, an edit, a window that no longer has the keyboard and a button held (a drag) end a rest, tell
the `leave` where there was a `dwell`, and tell nothing more until the pointer moves again. An answer
that comes late is written with the `version` the event carries: the editor carries it over what was
typed meanwhile as it does any decoration. The page reads the word at its own caret by the same rule
(`pencere.layout.word_at`), so that a command that does what the pointer's rest does (Show Hover) answers
as the rest does.

## What a reply may ask

`mods` is `{ shift =, control =, alt =, command = }`. A reply is `nil` (nothing changed), `true` or
`false` (a frame is worth drawing or not), or a table: `redraw`, `close`, `copy` (text for the
pasteboard; a host that keeps programs from its pasteboard, a terminal's `osc52 = "off"`, is told whether the person asked for it and writes it only if they did: a reply to a press or its release, a pick in a menu or a command the host's list asked for, and of the keys only the system's copy and cut, ⌘C and ⌘X (so also a command a key did: a page's command bound to ⌘C is the person's, one bound to any other key is not); not a reply to another key, to a message of the program, to a wake or to the room, whatever the page made the key do), `cursor` (`"arrow"`, `"pointer"`, `"text"`, `"resize_horizontal"`, `"resize_vertical"`,
`"not_allowed"`, `"grab"`, `"grabbing"` or `"crosshair"`; every reply to an input of the pointer says it, and one that says none, `nil` too, is the arrow: no shape is kept from an earlier reply, so a page that asks for one says it again at each move, press, release and turn of the wheel over what it is for), `keyboard` (`"page"` or `{ field = name }`),
`fill` (`{ [name] = text }`, or `{ [name] = { text =, select = } }`: what fields are to hold from now
on, and what is selected in them; `select` is `{ from =, to = }`, bytes from 1 ([Counting](counting.md)) in either order,
past the end the end (an end inside a character is where the character starts: a reply cannot be
told of a mistake), or `true` for all of it; a field given no `text` keeps what it holds, and one
given no `select` has its caret where its system puts it after a text, at the end; a name that is
not a field of the page is passed over, [Replies](replies.md)), `menu = { at = { x =, y = }, entries = { { title =, keys =,
enabled = }, "-", { enabled =, paste = editor } } }` (an entry's `keys` are written as a
command's, `"ctrl+w"` or `"f2"`, and shown at the end of its line; the line of a `paste` has no keys, and what is written there is not read: no key picks it; an entry has a `title` (a string, whatever else the page
puts in its table: a `key` of its own is the page's and is not read as keys), and the one string an
entry may be is `"-"`, a line between entries; a menu without `entries` is an error; an entry with `paste` is one the host performs itself when it is picked, [Replies](replies.md); the table of an
entry is told back with its pick, so a function or a field the page put in it is there when it is picked:
`menu` [Replies](replies.md)), `link` (an address to open in the person's browser, [Replies](replies.md)), `wake` (in how many seconds to wake the
page, [Replies](replies.md)), `text_size` (how many points larger than the host's own text the view is drawn, [Replies](replies.md)), `browser = { [name] = ask, or { ask, ... } }`, what the page asks of its browsers (`{ go = address }`, `{ zoom = size }`, or `{ command = "back" | "forward" | "reload" | "stop" | "find" | "find_next" | "find_previous" | "stop_finding" | "devtools" | "clear_cache" | "clear_site_data" | "proceed", ... }`, [Browser](browser.md); at most 64 asks in a reply, and a page that asks more fails; the address is held to its rule, a zoom to its range, a pattern to a search's, an ask the kit does not know is refused, and a browser the host has not made is passed over), and `editor = { [name] = ask, or { ask, ... } }`, what the page asks of its editors,
each ask one of:

**A pick is of the menu that was shown.** A host shows one menu at a time: a menu a reply asks for while
another is up is not shown, and the page is not told. So that a pick is never read against a menu the
person did not see, the kit gives each menu a reply asks for a number (`serial`, not the page's to
choose) and keeps the tables of its entries for the last sixteen; the host hands the number of the menu
it showed back with the pick (`pencere:view` `menu-pick`: the `serial` and the `index`), and the page is
told the pick with that menu's `entry`, the table the page wrote for the line, with its fields and
functions. `index` stays the line's place in that menu. A pick of a number that is not kept (a menu
asked for long ago, a menu picked from already, a number the page never had), or of a line that is
no entry (a rule, a place past the end), is not told the page: the entry of a menu the person was not
shown is not reachable by any pick. A page does not map `index` to its entries itself: `entry` is the
entry.

**A press that opens a menu.** `gestures` with `"context"` (`["right+press"] = "context"`) puts the caret
where a text view puts it for a press that opens a menu (VS Code's rule) and has the editor take the
keyboard: outside every selection it puts one caret at the place; inside one (at its ends too, and at a
caret) the selections stay. The press is then told the page as any (`press` with its `button`), with
the `place` it has: `{ editor, at, inside, version }`, where `inside` says the place was in a selection or at
a caret before the press moved the caret, and `version` is the editor's after; the page opens its menu from
that `press` (`menu` in its reply, at the press's `x` and `y`), and asks `copy`, `cut` and its other
commands of the editor when the entry is picked (those carry no version; an ask that does takes the
editor's current one, `pencere.layout.editor_version`, not the press's). A second press of the quick run
opens the menu as the first does. No `events` word is needed: the gesture is
the page's asking. A host whose system makes ⌃ with the main button a right press (a Mac's) may send it
as the main button with ⌃: the drive takes it for the right press where the page's `gestures` say a
right press does what opens a menu and say nothing of ⌃ with the main button, and tells the page the
press as the right button's, without the ⌃ (so does its release).
